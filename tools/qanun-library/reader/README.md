# Structured legislation reader

`renderLibraryReader(record, { sourceVerification, displayCorrections, sourceLayoutText, sourceArtifacts })` returns the reading HTML, sidebar navigation, stylesheet, provision locations and a transformation report. It consumes the existing source record and does not alter its text, ID, hash, passage contract or downloads.

The result has a structured `div#law-text` and a separate, exact original `pre#source-transcription` inside `details#original-transcription`. Every original passage fragment remains in the reading body. Its `data-passage-text` retains the searchable original passage; consumers should use that attribute rather than the empty anchor's text. Existing provision-fragment positions are also retained independently of the new navigation decisions.

## Source boundaries and content checks

Printed contents are separated only when an explicit source `TEXT` marker, legal recital, or first numbered provision identifying its own Act/Ordinance/Code establishes the body boundary. The exclusion stops at the printed heading list, before that boundary. A later dash-separated heading is never used as proof that earlier provisions are contents. Regression fixtures include the Cantonments Act, Pakistan Penal Code, Christian Marriage Act, General Statistics Act and KP Health Care Commission Act because their earlier provisions exposed this failure mode.

The report checks two sequences against retained source material: letters/numerals and every non-whitespace character, including legal punctuation. The latter reconstructs the declared source heading prefix and separator that the visual heading reformats; ordinary prose, list text, notes and layouts must retain their characters. An exact original transcription is independently retained, but merely retaining that hidden transcription does not pass the visible-content checks.

Explicit `Page n of m`, `n | P a g e` and `PDF PAGE n` markers can be omitted from the reading layout. Bare integers are retained because they may be legal text or source-note markers. Running titles are removed only directly after an explicit page marker and when they match the recorded instrument title. Every excluded range is reported.

Paragraphs reflow hard line wraps. Lists, provisos and explicit source notes receive distinct blocks. Apparent multi-row tabular/form layouts remain preformatted rather than being converted into guessed cells. Unknown structures retain their source text and are reported as ambiguities. The sidebar distinguishes main provisions from schedule paragraphs. Source contents may supply a heading label when the extraction separates a marginal heading from the numbered body; the actual body words remain intact.

Quoted/inserted provision text must not take the place of a differently named main provision from the instrument's contents. Tests include an inserted future-number section followed by the instrument's real provision with that number.

Schedule divisions recognise `THE SCHEDULE`, including a printed amendment-note prefix such as `1[THE SCHEDULE`, without absorbing that line into the previous contents title. Main-provision ranges end at the next provision or an earlier identified Schedule division. This keeps provision excerpts from crossing into Schedule material while preserving the complete visible body and original character offsets. The Pension Act regression checks its repeal title, separate Schedule and exact range boundary.

## Source-proven spacing corrections

`displayCorrections` is an array of zero-based original Unicode code-point ranges: `{ character_start, character_end, replacement: '' }`. Ranges must be ordered/non-overlapping, in bounds and contain only whitespace in the original text. Deleting any legal character is rejected. The caller must establish the correction against an independent original source; the reader performs the mechanical validation, not source authentication. Source offsets, original transcription, original text hashes and old anchors remain unchanged. The number of applied corrections is reported.

Deletions may cross CR/LF boundaries. The corrected character stream is rebuilt and relined using a retained-character map back to original Unicode code points. The old physical source lines, not the corrected lines, continue to supply legacy anchors.

For severely fragmented or differently wrapped extraction, `sourceLayoutText` accepts the independently extracted original's layout. Its complete sequence of non-whitespace characters must be exactly identical to the original record: no case folding, punctuation normalization, ligature substitution or omitted characters are accepted. The reader rebuilds the logical lines and maps every position back to the original character stream. This path can change whitespace only, and its text hash is recorded. The caller must select a genuinely independently verified original extraction; the mechanical equality guard alone is not source authentication. A source layout takes precedence over the deletion-only view, while supplied deletion ranges are still validated.

`sourceArtifacts` accepts independently confirmed numeric page-footer proofs: `{ character_start, character_end, text, input_text_sha256, source_pdf_sha256, source_page, reason: 'page_footer_confirmed_in_original' }`. The raw span must be exactly the digits in an isolated numeric source line, the input hash must match, the PDF hash/page must be supplied, and the mapped reading line must also contain only those digits. Any mismatch is rejected. Accepted proofs are recorded in `report.page_artifacts`; only their exact source ranges are excluded from the punctuation comparison. Ordinary numeric amounts, paragraph numbers and arbitrary bare integers cannot pass this validation.

`verified-layouts/manifest.json` contains independently extracted exact-character layouts for the eight initial paragraph-only cases. Six are readable text-bodied sources. Nursing Council 2025 and Defence Industrial Authority 2026 are image-bodied Gazettes: their matching text layers contain headers while most statutory pages are images. Those two layouts are not proof of complete readable legislation; they require a source-image reader or separately verified OCR and are marked accordingly.

## Complete original-page readers

`source-inputs.mjs` exports `loadSourceReaderInputs(record, sourceStatus)` for the release driver. It binds the six text layouts to the actual record hash, the audit's `stored_text_sha256` and `original.sha256`, and the independent layout byte/proof hashes. It reads `../source-pagination.json` and returns only footer proofs bound to the exact effective record and audited original PDF. Stale pagination rows for different reading versions return an empty artifact array. Known-layout proof mismatches throw. General spacing corrections remain the source officer's separate input.

`verifyFacsimileOutput(record, html, readerReport, output)` checks the published original PDF and every numbered source PNG, hashes, dimensions, order, page anchors, full-resolution links and truthful report scope. Use this branch instead of text-fidelity assertions for `readerReport.kind === 'original_facsimile'`; retain shared raw-download, exact transcription, mapping, unique/local anchor and source-register checks. Its return value reports `source_facsimile_pages` and `source_pdf_sha256`. Image citations require source-page/hash verification separately from text citations with character offsets.

`facsimile.mjs` provides `renderFacsimileReader(record, '/sources/facsimiles', {output})`. The optional `output` is the public build root. The function verifies every manifest-listed original PDF/page-image hash before rendering or copying; it copies only the PDF and numbered PNG allowlist into `output/sources/facsimiles/{record.id}`. The object-options form `renderFacsimileReader(record, {assetBase, output})` is also accepted. It returns the same HTML/navigation/CSS/report/provisions shape as the text reader, with no invented text provisions. `report.source_facsimile_pages`, `source_pdf_sha256`, `page_images_verified` and `source_body_text_unavailable` describe its distinct containment check. Word and punctuation invariants are null because the primary body is the original page image, not a machine transcription.

The four facsimiles include 133 original page images, full-resolution links and untouched original PDFs. Nursing and Defence Gazettes have header-only extraction; the Marriage Functions Ordinance 1999 has damaged OCR and uses its complete three-page original Gazette as the primary reading edition. Representation of the People Act 1976 uses all 59 selected Act pages from the held ECP volume: physical PDF pages 107–165, printed pages 131–189. Its untouched original download is the complete 281-page volume. The archived 2002 compilation is a different edition and has not been verified against the displayed source. `facsimiles/manifest.json` records source PDF/page-image hashes, original page dimensions and rendering scope. Extracted headers, damaged OCR or earlier compilations remain separately preserved in original-transcription details; legacy passage and section IDs remain available but do not imply that body text is reliably searchable. Do not present those extractions as a verified complete text search of these instruments.

`facsimile-frame.mjs` validates optional selected-source scope: `original_pdf_page_count` (canonical; `source_pdf_page_count` retained for compatibility), `source_page_start`, `source_page_end`, `selected_act_scope` and `source_edition_note`. Each selected page has a logical `page` for its `source-page-NNN` anchor and a physical `source_page` for the original PDF `#page` link. The original volume count and selected Act page count are displayed separately. Missing edition notes, inconsistent counts or non-contiguous/wrong physical mappings are rejected. The output verifier independently checks that the published frame/report uses those same physical page and edition bindings.

`facsimiles/reviewed-relationships.json` contains seven selected citation passages manually read from original page images, with exact source quotes (line breaks collapsed), original/printed page numbers, page anchors, image/PDF links and hashes. Five explicit references have matching held target records, including Marriage Functions' Article 89(1) recital and express notwithstanding reference to CrPC section 32. Two Nursing Gazette references preserve unresolved printed identities: the stated 2023 repeal and the source's “1987 (X of 1897)” General Clauses citation. These are source-stated identities, not silently corrected canonical links. Selected-passage review does not certify every statutory page or current force. `reviewed-target-passages.json` supplies held target openings with offsets/anchors; separate source audit owns target-source authentication.

## Verification

`supplements.mjs` provides `renderSourceSupplements(record, {output, assetBase: '/sources/supplements', sourceStatus})`, returning `{html, nav, css, report}` or null. Append its original graphic/form pages to the structured reader and its navigation to the existing sidebar. Merge its report metadata without replacing the main reader kind or extracted-text fidelity checks. `sourceStatus` is optional; when supplied, its original PDF hash must match. Every page links to its physical original-PDF page and full-resolution PNG; native checkbox rotation makes sideways original forms easier to read without altering the source image. The untouched complete PDF remains downloadable. Archived text and passage anchors are unchanged.

The supplements report sets `source_body_contains_untranscribed_images: true`, `full_source_body_text_checked: false` and `source_image_transcription_checked: false`. Text-fidelity checks cover retained extracted text; they do not certify graphic/form text. The public reader explains that source images supplement the searchable transcription.

Run `python tools/qanun-library/reader/render-supplements.py` to render the source officer's exact inventory at `sources/source-supplement-inventory.json`. The pipeline validates source/audit/input hashes and original physical page counts, copies untouched PDFs, and renders only the reviewed pages as full RGB144dpi PNGs. `supplement-assets/manifest.json` contains physical-page numbers, dimensions, PDF/PNG hashes and raw RGB pixel hashes. Rendering is incremental: existing assets are reused only after their hashes match. The inventory hash is bound into the manifest; a later inventory revision forces regeneration instead of silently omitting added pages. Do not copy the private manifest or tooling to the public site; the renderer copies only the verified PDF/PNG allowlist.

Then run `python tools/qanun-library/reader/verify-supplement-pixels.py`. This independent invocation re-renders every selected original PDF physical page and compares its RGB pixels with the decoded PNG. It writes a manifest-bound `pixel-verification.json`. `verifySourceSupplementsOutput(record, html, report, output)` verifies the published physical-page mapping, links, reports, PNG hashes/dimensions and complete original PDF hash; use it in the release verifier alongside the primary reader checks. `supplements.test.mjs` checks the published assets, input/source bindings, truthful image scope, corruption rejection, preserved records and independent pixel proof. Page/record totals follow the current reviewed inventory, which may expand after whole-source image screening.

Run `node --test --test-reporter=tap tools/qanun-library/reader/reader.test.mjs` from the repository root. The complete corpus test writes `coverage.json` only after examining every record and checks original text, visible content, punctuation, passage identifiers and duplicate IDs. `coverage-summary.mjs` reports aggregate results and the current module SHA-256. A coverage file from a previous module revision is not current evidence.

The test entry point imports `facsimile.test.mjs` and `source-inputs.test.mjs`: they check every manifest-listed PNG hash/native dimension and original PDF hash, source-page navigation, retained legacy extractions/anchors, verified allowlist copying, source bindings and citation-page bindings. Counts derive from the manifest. For a focused run without the repeated whole-library scan, use `node --test --test-reporter=tap --test-skip-pattern=whole tools/qanun-library/reader/reader.test.mjs`.

The reader's transformation checks do not establish original-source identity, amendment completeness, current force or the correctness of a legal interpretation. Those checks belong to the separate source and mapping records.
